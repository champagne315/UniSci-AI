# 硬件验证与设计评审

## 工作流

1. 把系统需求拆为可测量的性能、接口、环境、安全和可靠性要求。
2. 建立需求—设计—验证追踪关系，标出每项需求的测试方法、工况、设备和判据。
3. 在评审中核查电气、结构、热、制造、装配、维护和失效模式的相互约束。
4. 设计功能、边界、环境、寿命和异常工况测试，保留原始测量和偏差说明。
5. 对不通过项建立问题闭环：现象、影响、根因假设、修复、复测和设计冻结条件。

## 输出要求

- 交付验证矩阵、测试步骤、判定标准、风险清单和问题闭环表。
- 不以“测试通过”替代具体测量值、条件和容差。
- 对涉及人身安全、高压、高温或危险化学品的测试，先要求合规的安全审查。
- 需要模板时读取 `references/verification-matrix.md`。
